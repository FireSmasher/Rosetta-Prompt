# Rosetta Prompt

Renamed from Translate Prompt on 16 September 2026. The companion Mac app is `~/Applications/RosettaPrompt.app`, built from `Sources/RosettaPrompt/main.swift` in the Rosetta Prompt repository.

Turns a disorganized paste into a clean, well-structured prompt, grounded in the target model's own current prompting docs, then checks the result against written success criteria before handing it over. Always runs the actual rewrite through Claude Opus (the `opus` alias, which points at Opus 5.5 since 22 September 2026), so rewrite quality doesn't depend on which model happens to be running the interactive session, or on which model the finished prompt is destined for. The model is fixed; the effort level is not, since 5 September 2026 (see step 6).

Opus 5 was chosen empirically: a 4 September 2026 side by side test (haiku/low, sonnet/high, fable/medium, fable/high, opus/high) on the same disorganized prompt found Opus 5 produced the most concrete, best scoped rewrite of the five, at about half the cost of Fable 5.1 for the same task. The alias moved to Opus 5.5 on 22 September 2026 and that comparison has not been re-run on it. This holds regardless of which model the finished prompt targets, the rewriter and the target are separate choices (conflating them was a mistake caught in this skill's first build). One comparison, not a full eval sweep, if a rewrite ever looks weak or the user asks for a redo, re-test rather than assume the choice still holds.

## How to run it

1. **Get the messy prompt.** Use `$ARGUMENTS` if the user passed text after `/rosetta-prompt`. Otherwise ask them to paste it, then wait.

2. **Determine the target model.** Currently supported, one section per target across the two reference files: Claude Fable 5.1, Claude Opus 5.5, Claude Sonnet 5, Claude Haiku 4.5 (`reference/anthropic-prompting-guide.md`), and GPT-6 Astra, Sol, Luna (`reference/openai-prompting-guide.md`). Since 24 September 2026 the GPT targets are GPT-6 only: GPT-5.6 Sol, Terra and Luna still work but OpenAI no longer recommends them, and there is no GPT-6 Terra. Check the section headings in both files for the current list rather than trusting this one; new targets get added there, not here.
   - If the user named the target inline, use that, matched against the closest real section heading.
   - Otherwise score the prompt first: save it to a scratchpad file and run `python3 ~/.claude/skills/rosetta-prompt/scripts/score_prompt.py --file <messy.txt> [--context <ctx.txt>]` (add `--family openai` if the user wants a GPT target). It prints the recommended `model`, `effort`, `rewrite_effort` and the signals that fired, from the same rubric the app uses, at no cost. Then ask in one short question (AskUserQuestion, single question) with the recommended model as the first option, labelled `(Recommended)`, its effort and top signals in the description. Don't default silently: the target changes which reference section is used and materially changes the output.
   - If a name doesn't match anything in the reference files, say so plainly and ask them to confirm or pick from what's covered.

3. **Read only the relevant reference material**, if not already in context this session: "General principles" plus the section specific to the chosen target, from whichever file covers it. Don't pull in other models' sections, they're irrelevant noise. These are distilled, dated, sourced caches of each provider's own docs, not live fetches. If the relevant file is more than a few months old (check the date at its top) or a rewrite looks off, say so and offer to refresh it (see below), but don't do that automatically every run. Haiku 4.5 has no model-specific Anthropic page, so its section is short on purpose.

4. **Check for established context worth carrying over.** Step 6 is a fresh, isolated `claude -p` process with no memory of this conversation, so anything the messy prompt leans on that was already settled earlier in *this* session needs distilling into a short paragraph, or it comes back as guesses or literal placeholder brackets. Tested 4 September 2026: with vs without a distilled context paragraph cost almost the same ($0.141 vs $0.139), but no context produced `[MODEL NAME]`-style placeholders, while context named the real files and decisions. Skip this step when the prompt is self-contained, which is most of the time.

5. **Build the rewrite request.** Compose a single instruction that: states which model the rewrite is for; includes the general-principles text plus the target-specific section from step 3; includes the established-context paragraph from step 4, if any; includes the user's messy prompt verbatim, wrapped in its own tag; asks for exactly one output, the rewritten prompt itself, no preamble, no explanation, no markdown code fence wrapper; **carries a house_style block forbidding em dashes and en dashes anywhere in the output**, since the house style is no em dashes ever and a rewritten prompt is text the user pastes and uses (added 5 September 2026); tells it to apply only the techniques this prompt's complexity actually warrants, and **includes that file's "What NOT to over-apply" section verbatim** rather than merely referring to it; tells it to use established context to fill in specifics rather than leaving placeholders or guessing; and **states the success criteria it will be checked against** (the "What a good rewrite means" table in `reference/rewrite-evals.md`, in one short paragraph), so the draft aims at the same bar the checker uses. For Haiku 4.5, never ask for or mention an effort level: Haiku has no effort setting. A two-sentence ask should come back as a paragraph or two, not an XML-tagged essay with five examples.

6. **Run it through Claude Opus directly, always,** regardless of the current session's model or the chosen target:
   ```bash
   ENABLE_CLAUDEAI_MCP_SERVERS=false CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 claude -p "<the composed rewrite request>" --model opus --effort <low|medium|high> --output-format text --no-session-persistence --tools "" --strict-mcp-config --setting-sources ""
   ```
   The last three settings give the rewrite no tools at all (harness L3, added 16 September 2026): `--tools ""` drops the built-ins, `--strict-mcp-config` drops plugin MCP servers, and the environment switch keeps the claude.ai connectors, such as Gmail, from connecting. `--tools ""` alone still left 37 connector tools exposed. `--setting-sources ""` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` keep the user's own CLAUDE.md, memory and prompt hooks out of the call, so no personal context reaches the rewriter or leaks into the output. Always pass `--model opus` explicitly, never let this fall back to the interactive session's model. The model stays fixed no matter which model the finished prompt targets; only the reference material fed in, and the effort level, change.

   **Effort, changed 5 September 2026.** Use `rewrite_effort` from `scripts/score_prompt.py` (step 2; run it now if the user named the target and step 2 skipped it). Since 25 September 2026 the script does the scoring in code, the same tables and arithmetic as `Advisor.assess()` in the app, with any table in `reference/model-selection.local.md` replacing the default of the same name: class 1 to 4, mapped to effort (1=low, 2=medium, 3=high, 4=high, capped, except that a row in the `effort-by-model` table wins: Opus 5.5 gets `medium` at class 3, because its `medium` matches Opus 5 at `high`), floored at `high` if any stakes signal matches. The rewrite itself runs on Opus 5.5, so the same reasoning applies to the rewrite call. Scoring by eye drifted from the app; don't go back to it. Never quote or repeat the local file's contents in a rewrite: it is the user's private data and only steers the score. Don't default to `low` because most requests feel routine.
   - **Cap at `high`, never above.** A rewrite is one bounded generation. Anthropic reserves `xhigh` for "long-running agentic and coding tasks (over 30 minutes) with token budgets in the millions" (https://platform.claude.com/docs/en/build-with-claude/effort).
   - The effort a *task* needs and the effort *rewriting its prompt* needs are two different numbers. Deriving one from the other is a correlation, not an identity.
   - The 4 September comparison tested Opus 5 only at `high`. "Quality holds at lower effort on simple prompts" is an assumption, not a finding. If a rewrite of a simple prompt looks thin, raise the effort and re-test before blaming anything else.

7. **Check the draft before showing it (eval gate, added 16 September 2026).** Save the messy prompt, the draft, and any context paragraph to files in the scratchpad, then run:
   ```bash
   python3 ~/.claude/skills/rosetta-prompt/scripts/check_rewrite.py check --target <id> --original <messy.txt> --rewrite <draft.txt> [--context <ctx.txt>] --attempt <n>
   ```
   Target ids: `fable`, `opus`, `sonnet`, `haiku`, `sol`, `luna`, `astra`. If the request carried a suggested effort level, add one line naming it to the context file ("Effort level set by the difficulty score for <target>: <level>. The rewrite may state it."): the judge sees only the original and the context, so without it the effort line the guides ask for reads as invented and bounces a draft that passed every code check (the retry loop found 16 September 2026). The script runs the code checks first (dashes, placeholders, preamble, fence wrapper, leaked request tags, over-built or truncated length, target-specific lines the docs say to remove), then, only if those pass, one Sonnet 5 judge call with yes/no questions (intent kept, constraints kept, nothing invented, success defined, proportionate, plus the hallucination, consistency and prompt-leak guardrails where the task carries that risk). Criteria and thresholds live in `reference/rewrite-evals.md`. It prints JSON with `approved`, `retry`, `blocking`, `advisory` and `feedback`.
   - **If `retry` is true and fewer than 3 attempts have run,** go back to step 6 with the same request plus a `<previous_attempt_feedback>` block holding the `feedback` text and the rejected draft, and tell the rewriter to fix exactly those points and change nothing else. Then check again with `--attempt` raised by one.
   - **Stop after 3 attempts.** Show the last draft anyway, with its open `blocking` findings listed plainly. Never hide a failed check and never loop further.
   - **The judge is advisory until calibrated** (the harness rule in `reference/rewrite-evals.md`): its "no" answers get reported, but they neither retry nor fail a draft; only code checks do both. (Until 16 September 2026 its "no" answers also triggered a retry, which re-billed drafts that had passed every code check on almost every run.) `check_rewrite.py status` says whether it has been armed. Don't add your own extra judging on top; Opus 5 already self-checks.
   - If the judge is unavailable (CLI error, timeout), the script says so in `notes`. Report it in one line and continue with the code-check result.

8. **Show the user the result** in a fenced code block, ready to copy. Above it, one short header line, exactly:
   `Written for <target>. Sourced <date> · <percent>% confidence · Checks: <passed | passed, N judge notes | FAILED: ids> after <n> attempt(s).`
   Then one more short line giving the reason, matching the `confidenceNote` for that target in the app's `Target` array (`Sources/RosettaPrompt/main.swift` in the repository), the source of truth for these numbers; keep this skill in sync with it, not the reverse. As of 24 September 2026: Fable 5.1 and Sonnet 5 are 95%, primary Anthropic docs, sourced 16 Sep 2026; Opus 5.5 is 95%, sourced 24 Sep 2026. Haiku 4.5 is 80%, sourced 16 Sep 2026 from the general pages only, because Anthropic publishes no Haiku prompting page. GPT-6 Astra is 85% and GPT-6 Sol and Luna are 80%, all sourced 24 Sep 2026 from primary developers.openai.com docs; OpenAI publishes one GPT-6 guide whose behaviour notes were observed on Astra, so Sol and Luna get no confirmed per-model behaviour. These percentages are a judgment call about source rigor, not a number either provider publishes. If there are unresolved judge notes, list them in at most three short lines under the block. Don't re-explain what prompt engineering is.

9. **Offer to copy it to the clipboard** with `pbcopy` if they're likely to paste it elsewhere next, only if they ask or it's obviously the next step.

10. **Feed the failure library when the user rejects a result.** If the user says a rewrite that passed was wrong, or overrides a check, save it as a case (harness L5):
    ```bash
    python3 ~/.claude/skills/rosetta-prompt/scripts/check_rewrite.py save-case --target <id> --original <f> --rewrite <f> --expected <Rejected|Approved> --why "<their reason>" [--dest calibration]
    ```
    In the app, the "This rewrite was wrong" button above the result does this for them: it files the last result, with the exact context it was checked with, as a `Rejected` case with `--dest calibration`. Use `--dest calibration` for cases that should train the judge's calibration set (20 approved plus 20 rejected arms it, then run `check_rewrite.py calibrate`). After any change to the checks, the reference guides or the rewrite request, run `check_rewrite.py replay`; it must pass every case. After any change to the rubric tables, run `score_prompt.py test skill/evals/scorer/cases.json` (local, gitignored, 30 prompts with the expected rung); it must pass every case, and a prompt the user says landed on the wrong model belongs in that file.

## Your own data

The model and effort pick reads `reference/model-selection.md`, which ships neutral defaults. Personal examples and signals (the hover jobs per rung, the words that count as high stakes, domain vocabulary) go in `reference/model-selection.local.md`, copied from `model-selection.local.example.md`. It stays on the machine: it is gitignored, read only by the local scorer, and never sent to a model. Calibration and replay cases saved from real prompts are gitignored too (`evals/calibration/`, and every file in `evals/cases/` except the seed file), because they hold the user's own prompts.

## Refreshing the reference

Both prompting guides are caches, not live fetches. To refresh the Claude file: download each page as raw markdown (append `.md` to the docs URL and fetch it with curl; WebFetch returns only a summary), read it in full, re-distill only the affected section, and update the verification note and date at the top plus that target's `sourceDate` in `main.swift`. The pages are `claude-prompting-best-practices` and the per-model pages under `https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/` (check `https://platform.claude.com/llms.txt` for the current list; there was no Haiku page on 16 September 2026). A date must only ever claim what was actually read that day. To refresh the OpenAI file: re-search for the current model-specific docs (names and URLs there can change faster than Anthropic's), distill the same way, update only the affected section. The eval criteria in `reference/rewrite-evals.md` come from the develop-tests and three strengthen-guardrails pages under `https://platform.claude.com/docs/en/test-and-evaluate/`; refresh them the same way, then run `replay`.
